# 本地数据

默认金融数据集 Ethereum 包含 89 个以太坊地址和 15,869 笔真实 ETH 转账，按自然周划分为 13 个快照。89 个地址在演示开始前已选定。[来源、样本口径与复现命令](ethereum-eth/README.md)

EmailDept3 包含 89 个邮件节点和 12,099 次交互。原始归档保留 12,216 条，演示截取长空白前的连续活跃时段。合成样例包含 26 个账户。[EmailDept3](email-eu-core-dept3/README.md) · [合成样例](synthetic-small/README.md)

## 从工作台新增

在 **Dataset Loading → Import Dataset…** 选择一个 UTF-8 CSV。首行固定为 `u,v,t`，按下方字段规则填写至少一条交互。`u`、`v` 是无向连接的两个端点，顺序不限，节点 ID 保留前导零和大小写。`t` 统一使用 Unix 秒，原始毫秒值先除以 1000。只有相对秒的来源需要用已知起点换算。

导入以文件名作为显示名称，并保存至 `data/imported-*/`。后端按时间稳定排序，从每片交互的两端提取该片节点。同名同内容的文件重复上传会复用已有数据集。

观察窗口固定为 S01—S12，粒度取能覆盖输入时间范围的最小整分钟数并划成等宽窗口。截止取最新交互所在分钟的下一分钟起点，所以最新交互总在 S12。空片保留，S13 是下一预测窗口。导入完成后可以查询结构和挖掘历史，异常与预测需要匹配新数据集的模型。

## 演示中追加一片

点击 **Data Updates**，选择表头为 `u,v` 的 UTF-8 CSV，然后点击 **Append Snapshot**。文件描述该时刻的完整无向图。下面的示例包含一个三角形和孤立节点 `004`。

```csv
u,v
001,002
002,003
003,001
004,004
```

重复边和反向边合并。同一节点填在两列中可以声明该节点存在。只上传表头会产生一个空快照。系统沿用当前时间粒度，首次上传成为 S13，再次上传成为 S14。上一片进入历史后可选择它的时间范围运行挖掘。示例中以 `q=001、k=2` 查询，可得到前三个节点。

静态图记录连接的存在性。界面展示节点数、边数和核数，交互次数显示为 `—`。SLADE 和 Zebra 仅在匹配的原始数据版本上提供结果。本次追加仅在当前页面和后端进程的内存中生效，刷新后恢复基础数据。

## 原始图数据

原始交互按快照保存在 CSV 中，例如 `synthetic-small/S01.csv`。第一行为固定表头，之后每行代表一次交互：

```csv
u,v,t
a-001,a-002,1767232805
a-001,a-002,1767232805
a-002,a-001,1767232806.125
```

| 字段 | 含义 | 类型 |
| --- | --- | --- |
| `u` | 端点账户 ID | 非空字符串 |
| `v` | 另一端账户 ID | 非空字符串 |
| `t` | 自 1970-01-01 00:00:00 UTC 起的 Unix 时间戳，单位为秒 | 非负有限数值，允许小数秒 |

示例时间为北京时间 `2026-01-01 10:00:05`。禁止使用毫秒、日期字符串或快照编号代替秒时间戳。每行代表一次实际交互，重复的 `(u,v,t)` 也完整保留。同一时间戳按文件顺序稳定处理，不需要交易 ID。原始交互不保存金额、资产、交易次数或首位数字。

时间口径由 `manifest.timestamp_basis` 明确区分，默认 `unix`，合成样例继续使用 Unix 秒。Email Dept3 的官方数据只有从零开始的相对秒，标记为 `relative` 并保留原值；ISO 快照边界使用 UTC 1970 零点作技术编码，不能解释为真实日历日期。具体来源、固定截断边界、等宽划分及建议参数见 [Email Dept3 说明](email-eu-core-dept3/README.md)。

CSV 使用 UTF-8、英文逗号和固定 `u,v,t` 表头；读取支持 UTF-8 BOM、CRLF 换行与标准 CSV 引号转义。空快照仍保留一个只有表头的 CSV；缺失文件按数据缺失报错。表头、列数、数值和时间范围错误返回明确错误。

`observed.json` 仅保存 S01—S12 的 `{snapshot_id, present_accounts}`，`replay.json` 仅保存 S13 的同类节点配置，均不保存交互。节点集合用于表示孤立账户和区分账户缺席。`accounts.json` 保存节点清单和固定显示坐标，`manifest.json` 保存版本、快照边界及 `timestamp_unit="seconds"`。快照边界仍使用带时区的 ISO 日期字符串，逐笔事件的 `t` 统一使用数值秒时间戳。

读取层按请求只打开对应 `Sxx.csv`，并与节点配置组装为算法内存快照 `{snapshot_id, present_accounts, transactions}`，不再将这份内存对象写回 JSON。训练读取 S01—S11，当前检测读取 S12，只有主动观测接口读取 S13。HTTP 响应继续使用 JSON，前端无需直接解析 CSV。

读取后统一按节点 ID 排列端点。上例的三条记录归到一条 `a-001—a-002` 无向边，交互次数为 3。上传和离线转换保存统一排列后的端点，既有 CSV 直接沿用。自环行仍用于校验时间及保留节点，在图边、交互统计和模型输入中忽略。

结构查询按节点对建立无向简单邻接，SLADE、Zebra 和 UnderGS 使用保留真实时间和重数的无向事件。图接口按无序节点对累计 `transaction_count`，统计和画布使用同一条边。API 数据版本带 `-undirected-v1`，计算和模型校验均使用该有效版本。

清洗和构建快照的脚本放在 `backend/scripts/`，统一从后端配置取得此目录。数据读取实现在 `backend/app/repositories/`，数据格式遵循上层开发方案。

Ethereum、EmailDept3 及合成样例的演示快照纳入版本控制。读取层扫描一层子目录的 `manifest.json` 注册数据集，接口检查数据版本和观察截止。
