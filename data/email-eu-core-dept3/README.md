# Email Dept3 真实交互数据

数据集 ID 为 `email-eu-core-dept3`，接口有效版本为 `email-eu-core-dept3-v2-430dde7de92f-undirected-v1`。原始邮件数据有 89 名成员、12,216 次记录，时间跨度约 802.29 天。v2 截取长空白之前的活跃前段，保留全部 89 名成员及 12,099 次交互，跨度约 524.43 天，分为 13 个非空快照。节点编号沿用邮件数据的原始 ID。[SNAP Email-Eu-core-temporal 的 Dept3 部门子网](https://snap.stanford.edu/data/email-Eu-core-temporal.html)

## 文件与重建

```text
email-eu-core-dept3/
├── S01.csv ... S12.csv   # 逐笔已观测交互，固定表头 u,v,t
├── S13.csv              # 单独保留的未来回放交互
├── manifest.json        # 数据版本、时间轴和 S01—S13 边界
├── accounts.json        # 原始成员 ID 和确定性的固定圆形布局
├── observed.json        # S01—S12 成员清单，不含逐笔交互
├── replay.json          # S13 成员清单，不含逐笔交互
├── provenance.json      # 原始文件指纹、引用、转换规则、计数和建议参数
└── README.md
```

在 `demo/` 中运行：

```powershell
uv run --directory backend python -m scripts.import_email_dept3
```

默认读取 `data/raw/email-Eu-core-temporal-Dept3.txt.gz`，输出到本目录。也可通过 `--source` 与 `--output` 指定路径；相对路径基于命令执行目录，默认路径始终由后端配置解析。脚本仅转换本地文件，不联网，不修改原始压缩包，不覆盖其他数据集。每次重建应用相同的固定截断规则，版本指纹包含来源内容、转换器版本、截断起止、快照数量及宽度。替换现有数据包后重启后端，清除已读取文件的内存缓存；v1 请求返回 409，需重新读取数据集清单。

## 截断依据

按原始时间戳排序后，最大无交互间隔位于 `45,310,383` 秒与 `68,905,594` 秒之间，长度为 23,595,211 秒，约 273.09 天；第二大间隔为 596,254 秒，约 6.90 天。v2 的固定保留范围是 **`0 ≤ t < 45,310,384`**，保留长空白之前的全部 12,099 条记录，占原始记录的 99.04%，舍弃之后的 117 条记录。所有 89 个节点仍有保留记录。

边界依据时间分布确定，未依据社区成员数或异常分数调节。窗口内部的真实空闲时间完整保留，不删除空白后拼接时间，不按交互条数分桶。原始压缩包及其 12,216 条记录完整归档；`provenance.json` 同时记录输入、输出、舍弃数量、固定保留范围、两个最大时间间隔和来源指纹。

## 时间和快照

原始格式是 `u v t`，其中 `t` 为从未知起点开始的相对秒。转换与读取按节点 ID 统一排列两个端点，保留重复交互及原始时间戳，即 **`t_output=t_source`**。按时间稳定排序，同时间戳维持原始行顺序。

`manifest.timestamp_basis="relative"`，`timestamp_unit="seconds"`。为兼容当前 API 的 ISO 快照边界，以 `1970-01-01T00:00:00+00:00` 作为技术性的零点编码；这些日期只表达相对时间位置，不能当作实际邮件发生日期。SLADE 的时间差仍与原始数据一致。

保留范围重新划为 13 个等宽快照，宽度向上取整至整分钟：`60 × ceil((45,310,383 − 0 + 1) / (13 × 60)) = 3,485,460` 秒，即 **58,091 分钟，约 40.34 天**。快照均为左闭右开区间，第 i 片为 `[(i−1)×3,485,460, i×3,485,460)`。最后一个窗口结束于 45,310,980 秒，只在最后一条记录之后保留少量边界余量，不补造交互。

新 S01—S11 为历史，共 9,525 条；S12 为当前，1,208 条；S13 为后续观测保留，1,366 条。所有边界重新计算，不沿用 v1 的编号含义。新 S13 来自保留前段的最后一个窗口，旧长空白之后的 117 条记录不进入任何新快照。

原始文件没有出勤或离职信息，因此 89 名已识别成员作为固定名册出现在所有快照；无交互时为孤立节点，不表示该成员确实在线。布局仅由原始 ID 决定，不使用 S13 拓扑。

## 读取和算法

后端自动扫描本目录的 `manifest.json` 注册数据集，普通快照接口拒绝 S13。历史算法仍按单快照作无向简单投影，聚合图仅用于展示。周期默认 `account="49", k=4, epsilon=1`，持久默认 `account="49", k=3`，爆发默认 `l=3, delta=5.60`。建议账户仍只依据 S01—S11 历史并集投影的度数选择，同分按数值 ID 升序选择。导入器的推荐参数和前后端读取同一份 [默认配置](../../config/README.md)。

当前默认参数下的确定性结果为周期 35 人（周期长度 2、重复 3 次）、持久 76 人（S01—S06 形成、稳定至 S10、持续 4 个快照）、爆发 45 人。S12 局部 core 默认 `q=49,k=7`，返回 30 人，与最大非空 7-core 一致；密度默认 1，返回 6 个三人结构。局部 k=8、持久 k=16、爆发 δ=6.667 均为空；周期 k=5、6 在 ε=0 时仍为空。若手动使用旧参数 k=4／δ=3，仍得到先前 35／73／70 人历史结果和 57 人当前局部 core。这些是当前划分和实现的计算结果，不是原论文报告或数据集真值。

03 默认展示 S12 的 89 个节点和 320 条无向边，共累计 1,208 次交互。SLADE 模型 `slade-d73301cecdf93996` 用 S01—S11 的 9,525 次无向交互在 cuda:0 上训练 10 轮，随后在 S12 为 88 名账户评分。另 1 名无交互历史的账户单列。

在 `demo/` 下运行 `uv run --directory backend python -m scripts.train_slade --dataset email-eu-core-dept3` 可重建模型，产物位于 `models/email-eu-core-dept3/slade/`。本次 GPU 训练约 49.96 秒，峰值显存分配 124.04 MiB，损失从 9.47119 降至 9.30165。尚未提供未来份额预测，预测接口继续返回未接入（503）。该数据没有异常真值标签，不能由排名计算真实检测准确率。
