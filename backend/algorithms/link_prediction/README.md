# Zebra 下一快照链接预测

算法依据：[Zebra: When Temporal Graph Neural Networks Meet Temporal Personalized PageRank](https://www.vldb.org/pvldb/vol16/p1332-li.pdf)，PVLDB 16(6):1332–1345，2023；[作者代码](https://github.com/LuckyLYM/Zebra)。本实现的方法版本为 `zebra-window-v1`。UnderGS 已作为独立备选模型接入，复现机制与训练结果见 [UnderGS 说明](undergs/README.md)。

## 任务与输入

输入为 CSV 中的 `u,v,t` 逐笔无向事件。加载时统一排列端点并滤除自环。重复交互与同时间戳记录均保留，以 `(t, 原行序)` 稳定排序。时间编码使用相对数据起点的真实秒数，先在双精度中求差，再转为模型浮点张量。节点没有额外属性，边属性采用单维零向量。真实账户 `"0"` 与内部 padding 0 分开映射。

截至 S12，预测每个无序顶点对在 S13 内是否至少出现一次交互。候选包含已有连接和未连接的不同节点对，每对保留一个标签和一个独立概率。全图历史决定模型状态，社区选择限制输出范围。

## 论文机制与工程适配

保留的机制：GRU 记忆更新、作者固定余弦时间编码、SANTA 流式 Top-K T-PPR、归一化 T-PPR 权重聚合、多个尺度表示拼接及成对 MLP。源节点变换与邻居变换为独立的两层 MLP；最终表示为源节点及两种 T-PPR 聚合的拼接。T-PPR 中保留的是带事件编号和时间戳的时间邻居，不是去重账户。β 作用于事件递推，真实间隔另外由时间编码表达。

`tppr.py` 用标准库容器和双精度数值实现作者 SANTA 递推；一次事件的两个端点均读取更新前的邻域。Top-K 同分按 `(event_id,node_index,timestamp)` 升序固定选择。与作者代码的无截断小图逐项对照最大误差为 `1.39e-17`；同分截断顺序属于明确的工程约定。

本项目与原论文事件级实验的差异：

- 监督目标改为下一完整快照的存在性标签，不把某个时刻的原始事件评分解释为窗口概率。
- 每个真实事件更新两端记忆；不使用原训练脚本的批末 last-message 缓冲。快照内保留梯度，快照间截断反传。
- 对称化解码器输出，保证无向概率：`logit(u,v) = (MLP(z_u,z_v) + MLP(z_v,z_u))/2`。
- 固定窗口头通过 `sigmoid(logit/T)` 输出概率，温度 T 只在 S11 标签上拟合，范围 `[0.05,10]`。不做分类阈值或社区内归一化。
- 枚举截至输入快照已出现账户的全部顶点对，使用未加权 BCE；不采用原文事件级的随机负采样。

这些适配保留 Zebra 编码机制，但不是原论文事件级实验结果的原样复现，也不宣称原论文的性能或加速倍数。

## 训练与时间隔离

从项目 `demo/` 目录执行：

```powershell
uv run --directory backend python -m scripts.train_zebra --dataset email-eu-core-dept3
```

| 阶段 | 可用输入 | 标签 |
|---|---|---|
| 训练 | 截至 S01，依次至 S08 | S02，依次至 S09 |
| 选模 | 截至 S09 | S10 |
| 校准 | 截至 S10 | S11 |
| 独立回测 | 截至 S11 | S12 |
| 页面预测 | 截至 S12 | 不读取 S13 标签 |

每轮清空状态、按时间前向；每个训练窗口做一次参数更新。验证前用当轮固定参数重新回放 S01—S09，按 S10 的未校准对数损失选择最佳轮次，相等时保留较早轮次。选择后冻结模型，重放至 S10、拟合 T，再推进 S11 形成预热状态。S12 仅在上述步骤完成后打开，作为独立回测，不参与调参。页面从 S11 预热状态推进真实 S12，评分截止恰为 S12 结束时刻。

默认：记忆、节点、时间维度均 100；Top-20；`(α,β)=(0.1,0.5),(0.1,0.95)`；聚合 dropout 0.1；Adam `1e-4`；最多 50 轮，连续 5 轮验证损失未改善停止；种子 `20261116`。温度校准无两个类别时使用 T=1 并记录原因。数据必须有 11 个历史、1 个当前、1 个未来的连续等宽快照。

指标包括 AP、ROC-AUC、Brier、对数损失、候选及正例数量。基线为最近一片的存在性、最近三片的交互频率；同时报告当前已有连接和未连接两组，以及因截止时尚未出现账户而无法评估的正例数。所有回测在完整候选空间完成，不只评价所选社区或 Top 边。

## 环境与模型产物

使用现有 Python 3.10、PyTorch 2.8.0+cu128、NumPy。代码不要求 Numba、PyG、torch-scatter 或旧版本依赖；未更改任何依赖配置、锁文件、虚拟环境。模型和账户记忆在 cuda:0 上；SANTA 字典与指标计算在主机上。缺少 CUDA 明确报错，不回退 CPU 训练或推理。

产物位于 `models/{dataset_id}/zebra/{model_version}/`：

- `checkpoint.pt`：张量权重、账户映射、S11 记忆和 T-PPR 状态、温度。
- `manifest.json`：方法、配置、数据版本与历史事件指纹、窗口划分、训练曲线、校准与回测报告、CUDA/显卡/耗时。
- 上级 `current.json`：通过恢复一致性与 S12 评分一致性检查后，原子切换的服务指针。

加载使用当前 PyTorch 的 `weights_only=True`，不反序列化旧代码中的模型对象。校验文件哈希、数据指纹、时间配置及状态维度；模型缺失/损坏/GPU不可用返回 503，版本或历史指纹冲突返回 409。

## 在线预测与模块边界

`model.advance` 仅接受已发生事件；`encode / pair_logits / all_pairs` 只读状态。不得用候选边调用历史更新。`app/services/link_prediction.py` 按数据、历史和 S12 指纹、模型版本与截止缓存完整成对概率；访问由锁保护，缓存只保存 CPU 结果，不跨请求共享可变 GPU 记忆。社区筛选不重新编码、校准或归一化。

截止时无交互历史的账户列入未评分清单，相关顶点对不填虚构概率。没有候选、没有历史、请求失败分别返回明确状态。普通接口、模型目录、训练与回测均不调用读取未来观测的 `Repository.replay()`，也不读取 S13 CSV；旧观测接口独立保留。

## 已训练结果

Dept3 无向基础模型 `zebra-4361fbd78cb2a8ba` 采用第 24 轮，训练耗时 275.339 秒。S12 回测 AP=0.2492、ROC-AUC=0.7864、Brier=0.0700、对数损失=0.2483。页面使用 S11 校准后的 `zebra-a55d8f6ef5de5b56`，S12 回测 Brier=0.0515、对数损失=0.1941。

未来社区查询复用全图概率，对历史候选成员以概率严格大于所设阈值建图，提取包含查询节点的预测 k-core 连通分量。完整训练报告、基线定义和时间隔离见 [工程验证记录](../../../VALIDATION.md)。
