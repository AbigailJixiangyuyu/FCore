# UnderGS 下一快照链接预测

依据 [Understanding Evolving Graph Structures for Large Discrete-Time Dynamic Graph Representation](https://www.vldb.org/pvldb/vol19/p862-xu.pdf)，PVLDB 19(5):862–875，2026，及[作者代码](https://github.com/dani0108/UnderGS)。本实现采用 GCN 骨干，方法版本为 `undergs-window-v1`；它与 Zebra 独立训练，可在同一预测接口中切换。

## 输入与核心计算

输入为按现有窗口划分的 `u,v,t` 无向交互。每条非自环记录分别为两端增加一次交互计数，重复交互逐笔累加。邻居集合和最短路径使用无向简单图。无额外节点属性时初始表示为零，边特征为单维零向量。账户在其真实交互被处理后才进入模型映射。

`tcns.py` 按论文式（1）计算节点重要性。令 r_i 为该快照内的交互次数，N_i 为去重邻居集合：

```text
C_i = sum(exp(r_i/r_j), j∈N_i 且 r_j≥r_i)
    + sum(exp(-r_i/r_j), j∈N_i 且 r_j<r_i)
I_ij(t) = C_j(t') × α1^(l−1) × α2^(t−t')
```

每个完整快照先计算全部 C_i，再对每个账户枚举最多 L=2 跳的最短路径；排除自身，同一账户在同一快照只保留最短路径候选。同一邻居在不同快照中分别占用记录，键为 `(account_id, snapshot_index)`。推进快照时旧权重乘一次 α2，与当前候选合并后保留 Top-K。同分按账户 ID、快照序号升序；空快照同样推进时间衰减。该过程不依赖原始记录或节点遍历顺序。

邻居索引、快照位置、float64 影响权重以及 float32 节点表示均持久保存在 cuda:0；CPU 只承担 CSV 解析、计数、无向投影和两跳候选准备。权重排序和最终邻居库更新使用当前 PyTorch，不要求 Numba、PyG 或 torch-scatter。

`model.py` 在同一个更新前节点表示上同步计算全部已知账户的新表示：邻居消息拼接上一快照表示、零边特征和余弦时间编码，经过两层 MLP；源表示另经两层 MLP，再将源表示与邻居聚合拼接、线性更新。当前无交互的已知账户继续利用历史邻居。时间编码使用快照编号差，快照内部精确秒数和记录顺序不进入编码。

## 与原文、作者代码的差异

- 以论文的完整快照交互次数、两跳路径、时间衰减和历史邻居记录为准。修正作者代码的去重计数、邻居库更新未写回持久数组等问题。
- 本次损失直接使用带梯度的节点表示，不经过 `detach` 的特征缓冲。编码器和成对预测头联合训练，窗口更新完成后才截断历史梯度；每轮同时重置邻居库与节点表示。
- 论文式（13）直接累加 I_ij 加权消息；本实现保留作者 GCN 代码的行权重归一化。历史屏蔽后重新归一化，权重和为零时聚合为零。未归一化的前向检查会使本数据上表示随快照数快速增长，因此不将该处理隐称为论文原公式。
- 历史记录独立按 Bernoulli(1−ρ) 屏蔽，当前快照记录不屏蔽。屏蔽不改写持久邻居库；只在训练启用，验证、预热和在线推理关闭随机屏蔽及 dropout。
- 训练目标采用本项目的下一完整快照存在性标签，预测当前输入的全部已知账户对，不使用作者事件接口在评分时写入候选边。编码器输入仅到 t，t+1 只作为标签。
- 无向 logit 是交换两端后的 MLP 输出均值，输出 `sigmoid(logit/T)`。采用全部无序对的未加权 BCE，不做负采样或类别重加权；温度只在 S11 标签上拟合。
- 候选对按最多 200 对分批，按候选数合并为整个窗口的平均 BCE；窗口末才更新一次参数。最后不足 200 对的批次不获得额外权重。这是面向现有小图的窗口实现，不声称复现原论文的大图吞吐量。

## 固定配置与训练

| 参数 | 默认值 |
|---|---|
| 节点／时间维度 | 128／8 |
| 邻居 K／路径 L | 16／2 |
| α1／α2 | 0.1／0.05 |
| 历史屏蔽率／dropout | 0.3／0.1 |
| 优化器 | Adam，lr=1e-4，weight_decay=0 |
| 候选对批大小 | 200 |
| 轮数上限／早停耐心 | 50／5 |
| 随机种子／设备 | 20261116／cuda:0 |

Dept3 训练输入快照的平均无向密度约 0.0832，高于论文配置分界 1e-4，采用屏蔽率 0.3。该值作为本轮固定配置，不根据 S12 效果调节。

从 `demo/` 执行：

```powershell
uv run --directory backend python -m scripts.train_undergs --dataset email-eu-core-dept3
```

| 阶段 | 输入截止 | 标签 |
|---|---|---|
| 训练 | S01…S08，每次含此前全部历史 | S02…S09 |
| 选模 | S09 | S10 |
| 温度校准 | S10 | S11 |
| 冻结后的独立回测 | S11 | S12 |
| 页面预测 | S12 | 不读取 S13 |

按 S10 未校准对数损失选模，同分保留更早轮次。最终参数重新回放至 S10，以 S11 标签拟合温度并限制在 [0.05,10]，无两个类别或校准未改善时 T=1；再处理 S11 导出一致预热状态。只有上述步骤结束才读取 S12 做回测。API 从 S11 状态推进真实 S12，评分只读，不更新模型或插入候选。训练、目录查询和预测都不调用未来观测接口。

## 产物、接口与缓存

产物为 `models/{dataset_id}/undergs/{model_version}/checkpoint.pt` 和 `manifest.json`；上级 `current.json` 独立于 Zebra。保存当前权重、账户映射、S11 节点表示和邻居库、温度、配置、事件指纹、训练曲线、指标及运行环境。使用当前 PyTorch 的 `weights_only=True` 加载，核对校验和、状态维度、邻居键和时间边界。保存恢复及继续处理 S12 的结果精确一致后才激活。

`GET /api/datasets/{id}/link-prediction/models` 分别报告两种模型。`POST /api/link-prediction/predict` 指定 `model="undergs"`，返回社区内全部无序顶点对，`method=undergs-window-v1`、`result_kind=computed`。缺失、损坏或 GPU 不可用返回 503；数据指纹冲突返回 409，不自动切换 Zebra。成员顺序先规范化再核验完整结构，成员、哈希或提交条件变化仍拒绝。

服务缓存按模型名称、版本、数据版本、历史与 S12 指纹、观察截止隔离，只缓存 CPU 概率与已知账户集合。每次重新推理独立恢复 GPU 状态，锁保护并发计算。全图表示决定分数，社区筛选保留每对账户的原始概率。

## 本次 Dept3 结果

基础版本 `undergs-d00b82e22d5c3ee9` 匹配 `email-eu-core-dept3-v2-430dde7de92f`。在 Python 3.10.11、PyTorch 2.8.0+cu128、RTX 5060 Laptop GPU 上完成 50 轮，采用第 50 轮，训练及校准耗时 40.020 秒，峰值显存分配 71.73 MiB，温度 0.87073922。源变换、邻居变换、节点更新和预测头均得到有限非零梯度。

S12 回测使用 3,828 个候选对，其中 320 个正例；没有因未出现账户而漏评的正例。

| UnderGS | 0.147312 | 0.735381 | 0.076989 | 0.288972 |
| 已有 Zebra | 0.246564 | 0.786496 | 0.070002 | 0.247585 |
| 最近 S11 是否连接 | 0.334629 | 0.696563 | 0.064263 | 1.775662 |
| 最近三快照出现频率 | 0.511911 | 0.810107 | 0.049315 | 0.878433 |

基础 UnderGS 的已有连接组为 188 对、131 个正例，AP=0.751276，未连接组为 3,640 对、189 个正例，AP=0.086110。页面使用按无向口径重训并经 S11 校准的 `undergs-ea61cb576ce05a4b`，S12 回测 Brier=0.0533、对数损失=0.2032。
